# 扫描页、上下文与新书首批

仅在处理扫描 PDF、图样/规格表密集章节、上下文压缩后的恢复，或新书首批前置页时读取。

## 扫描页与上下文控制

扫描书必须避免把整批页面图片写入会话。一次发送整个语义批次的高分辨率扫描页会迅速占满上下文、反复触发自动压缩，并使本地会话文件增长到数百 MB。

- 渲染本批页面后，用本机 OCR 一次生成临时文本。例如：

  ```powershell
  powershell.exe -NoProfile -ExecutionPolicy Bypass -File "manufacturing-document-qa\scripts\ocr-images.ps1" -InputDirectory "_qa_work\tmp" -FilePrefix "书名-page-" -StartPage 57 -EndPage 64 -OutputPath "_qa_work\tmp\书名-ocr-0057-0064.txt"
  ```

  初始 OCR 页码范围应与默认 `Plan` 一致。若候选窗口最后一页的知识点尚未闭合，应先用更大的 `BatchPages` 修订 `Plan`，再只 OCR 新增的相邻页；多个 OCR 片段按页码顺序阅读即可，不必重复识别已有页面。用于生成问答的 OCR 页码必须落在最后一次 `Plan` 的范围内；若最终边界前缩，超出最终范围的已读页面只算边界预览，不得生成本批问答，并随本批临时文件一起删除。不得带入其他书籍或不连续的后续批次。
- 先根据 OCR 文本提取普通正文。OCR 可能把 `G15`、`G18`、小数点、负号和直径符号识错，也可能把公式整行漏掉。凡页面含公式、数值关系、代码、表格、结构图或角度/尺寸关系，无论 OCR 是否看似连贯，都必须回看对应原图确认。对于以图样、结构简图或规格表为主体的页面，OCR 不能保留字段关系，应直接视为“需要回看原图”，不能仅凭标题生成一条笼统问答后跳过全页。
- 禁止一次向模型发送整个语义批次的全部高分辨率页面，也不要重复查看同一页。先用 OCR 建立逐页知识单元清单；普通叙述页不必查看原图，但含上述精确关系的页面必须逐张查看一次。优先确认公式符号、表头、单位、适用范围、结构动作和选择关系；只含无法脱离图面表达的尺寸标注或重复结构时才跳过。
- 查看原图默认使用普通高细节，不使用 `original` 或额外的 4 倍渲染；只有单页关键小字无法辨认时才临时提高分辨率，并在提交后删除。
- OCR 文本、渲染图片和临时提取脚本都属于当前批次临时文件，`Commit` 成功后立即删除。

## 图表型批次的低产复查

若批次通过数量低于 `ceil(技术页数 × 3)`，`Commit` 会保留批次文件、拒绝写入并保持 `next_page` 不变。收到此错误后：

1. 按页核对是否遗漏夹具/刀具/工艺类型的用途、适用对象、动作原理和结构差异。
2. 对规格表核对是否能形成“给定工件范围如何选择规格”“某规格覆盖什么范围”“不同规格差异是什么”等独立查询；不要逐单元格机械拆问。
3. 对技术要求核对精度项目、基准关系、适用条件和判据；只有能够补全对象与基准含义时才生成，不能保留 `F 面`、`R 面` 等依赖当前图样的孤立代号。
4. 核对临时 `coverage`：最终页码范围内每页必须有条目；每个定义、公式、条件、选择关系和判据必须拆成具体源页事实并填写 `source_type`、`source_fact`，再关联候选问题或写明 `skip_reason`；非技术页必须填写 `reason`。凡写“已有问答充分覆盖”，还必须以 `covered_by` 列出实际存在的精确旧问题，不能以同主题的概括问题替代。
5. 补充遗漏记录后，用原 `BatchFile` 重新执行普通 `Commit`。只有逐页复查后确认剩余内容确实无法形成独立问答，才使用 `-LowYieldReviewed` 重新提交；不得把技术页标成非技术页或缩小页码范围来绕过门禁。

每次成功提交会在 `state.json` 的 `recent_commits` 中保留最近 20 次统计。出现产量下降时先查看 `candidates`、`added`、`skipped` 和 `yield_per_page`，判断是生成不足还是过滤过多，不再依赖临时批次或会话记忆追溯。

回检已处理页时同样执行上述逐页原图规则，但已有 JSONL 只能在源页知识单元清单完成后用于去重。先看已有问题再找遗漏会产生锚定效应：概括性问题容易掩盖同页未覆盖的数值范围、成立条件、材料差异和选择限制。回检时先写“源页具体事实 → 原子知识单元”，再逐个决定新问题或可核验跳过；不得以“本页内容已有覆盖”的整页结论替代这一步。回检批次使用 `Augment`，其统计写入 `augmentation_commits`，且不得改变正常阅读的 `next_page`。

自动上下文压缩只影响当前会话，不会推进或回退书籍状态。压缩或中断后先 `Resume` 核对 `book_id`、`next_page` 和 `record_count`；状态未推进时继续原批次，状态已推进时只清理临时文件并汇报，禁止重新提交。旧会话若已反复压缩或持续出现停止状态，应新建会话并用同一 `book_id` 执行 `Resume`，不要继续向超大会话追加扫描图片。

## 新书首批的前置页过滤

新书第一个批次通常混有封面、版权页、前言、目录、知识目标、能力目标和任务描述。生成前先区分“出版/教学信息”和“可迁移的制造技术知识”；前者跳过，不得为了达到通常条数而转成问答。首批只有 1～5 条高价值技术问答时，逐页确认其余内容均属前置元信息后，可用 `-LowYieldReviewed` 提交。

- 跳过书名、作者、出版社、课程定位、适用读者、编写思路、教学组织、章节安排、知识目标、能力目标、学习目标、引导案例名称和“完成任务后会做什么”等内容。
- 不把目标页中出现的 G/M 指令、软件名、设备名或术语清单直接改写成分类、含义、格式或用途问答；只有正文明确解释了技术含义、适用条件或操作方法后才能生成。
- 去掉“项目一”“任务二”“本课程”等教学框架后，如果问题不再成立或答案只是在复述“学习、掌握、了解、具备”，直接丢弃。
- 案例图上的孤立尺寸、厚度、编号、评分值或任务规定，只有在问题完整说明零件结构、材料、装夹、加工目标等必要上下文，且该数值用于编程计算、工艺选择、质量判定或故障分析时才保留。
- 前言或任务描述中的操作名词清单，只有能改写为制造现场可直接检索的技术问题时才保留；不得保留“通过该任务需要掌握什么”之类教学口吻。

提交前快速判断：不提书名、项目号和任务号后，这是否仍是制造从业者可能提出的问题？答案是否给出了稳定的技术事实、条件、方法、参数关系或判据？任一项为否就丢弃。
