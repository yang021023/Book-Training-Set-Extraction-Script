# 制造书籍批量问答生成

目标是尽快把大量书籍转成数量充足、能脱离原书理解的训练问答。默认是“批量生产模式”，不建立审计型证据链。

## 文件结构

```text
工作区/
├─ 书名.pdf
├─ 书名.jsonl
├─ _qa_work/书名/state.json
└─ manufacturing-document-qa/
   ├─ SKILL.md
   ├─ agents/openai.yaml
   ├─ package.json
   ├─ package-lock.json
   └─ scripts/
```

- 最终 JSONL 每行只含 `messages`。
- 每本书只长期保留一个小型 `state.json`，记录 PDF、JSONL、总页数和下一页。
- 不建立 ledger、逐条 evidence、reviewer、逐页检查表、拒绝记录、Markdown 报告或长期截图/OCR 缓存。
- 临时批次放 `_qa_work/tmp`，提交成功立即删除。
- PDF 解析依赖由 `package.json` 和 `package-lock.json` 声明，不把 `node_modules` 或 Node 可执行文件提交进 Skill。首次使用或依赖缺失时，在工作区运行 `npm install --prefix manufacturing-document-qa`；随后 `.mjs` 脚本只读取 Skill 内安装的 `node_modules`。

## 默认批量生产

### 会话与书籍绑定（硬约束）

- 一个会话最多处理一本书。新会话首次选定、`Resume`、`Plan` 或处理某本书后，该会话即永久绑定这个 `book_id`；绑定在整个会话生命周期内不可更换，包括该书完成以后。
- IDE 活动文件、打开的 OCR 标签和用户后续提到的其他书名，只能在会话尚未绑定时用于选书。会话一旦绑定，任何这些变化都不得触发切书。
- 绑定书完成后，用户再说“继续”“接着”“下一批”“往下做”等，只允许对原 `book_id` 执行 `Resume` 或直接依据已核对状态报告“该书已完成”，随后停止。严禁 `List` 后选择另一书，严禁对另一 `book_id` 执行 `Resume`、`Plan`、提取、渲染、OCR、创建批次或 `Commit`。
- 即使用户在已绑定会话中明确要求处理另一书，也必须停止并提示其新建会话；不得在当前会话切换。新书只能在新会话开始。
- 一本书可以因上下文长度而由多个会话先后接力，但旧会话必须停止，不能与新会话同时处理；新会话使用同一 `book_id` 执行 `Resume`，以 `state.json` 为准。
- 若发现当前会话已经触及第二本书，立即停止第二本书的未提交工作并清理其当前批次临时文件，不得继续提交。若第二本书已被误提交，不得自行删除记录或回退状态；应报告涉及的 `book_id`、页码和记录数，等待用户在正确会话中决定如何处理。

#### 继续请求的决策门禁

每次收到“继续”“接着”“下一批”等请求，先按会话历史判断是否已有绑定的 `book_id`，再决定是否调用脚本：

- 已绑定且书籍仍为 `active`：只允许对该 `book_id` 执行 `Resume`、`Plan` 和当前批次流程；不得用 `List` 重新选书。
- 已绑定且书籍为 `completed`：只允许对该 `book_id` 执行一次 `Resume` 核对，或直接报告已完成，然后停止；不得把“继续”解释为“下一本”。
- 尚未绑定：只有用户明确点名书籍，或 `ActiveFile` 唯一映射到一本书时才能绑定；若“继续”无法唯一确定书籍，列出状态后必须等待用户指定，不得因只剩一本 active、活动标签变化或最近打开的 JSONL 而自行绑定。
- 绑定判定完成前不得创建批次、提取页面、渲染、OCR 或 `Commit`；所有脚本调用都必须显式使用与绑定一致的 `-BookId`。发现拟调用的 `BookId` 与绑定不一致时，立即停止并请求新会话。

1. 仅在新会话尚未绑定书籍时运行 `powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts/qa-work.ps1 -Action List`。用户点名或 IDE 有 `Active file` 且能唯一映射时直接 `Resume` 对应书；首次绑定后保存 `book_id`，后续所有 `Resume`、`Plan` 和 `Commit` 都必须显式使用这个 `book_id`。已绑定会话即使书籍完成，也不得通过 `List` 选择下一本。
2. 使用 `Plan` 取得连续 8 页；普通批次必须使用脚本默认的 8 页，不得预先显式传入更小的 `BatchPages`，也不得因为之前发生过超时、会话错误或上下文压缩就主动改成 2–4 页。到书末自动缩短，绝不越过 PDF 实际页数。一次用户“继续”只授权当前一批和最多一次 `Commit`。`Commit` 成功后，本回合只允许删除当前批次临时文件、用 `Resume` 核对状态并向用户汇报；禁止再次调用 `Plan`、提取或渲染下一批页面、创建下一批文件或执行第二次 `Commit`。单独的“继续”不表示连续运行；只有用户明确要求“连续处理 N 批”“处理到第 X 页”或“完成整本”时，才可在同一回合处理多批。
3. 优先提取 PDF 文本。文本层为空或明显损坏时才渲染对应页；扫描页渲染后先使用 [ocr-images.ps1](scripts/ocr-images.ps1) 做本地中文 OCR，再阅读 OCR 文本。只有 OCR 无法确认的公式、表格、图样和精确 G/M 代码才查看原图。不得因为上一批是扫描页就跳过本批的文本提取检查。
4. 阅读当前批次后直接生成问答，并在生成时完成一次轻量检查。不要先保存候选、证据、拒绝项，再启动另一轮逐条复审。
5. 把准备写入的记录组成临时批次，执行 `Commit`。脚本只保留通过硬门禁且不与现有问题精确重复的记录，原子更新 JSONL 和 `state.json`，随后删除临时批次。
6. 每新增约 100 条或整书完成时运行一次 `validate-jsonl.ps1`。普通警告只供抽查，不阻止继续；不要每批重复扫描整本 JSONL。

一个批次通常应产生约 15–50 条。正文稀疏时可以更少，高密度表格、工艺步骤或指令页可以更多。数量是漏项提示，不是凑数配额：优先检查定义、作用、适用条件、选择方法、参数与单位、步骤、比较、缺陷原因和结果判据。

处理扫描 PDF、上下文压缩后的恢复，或新书首批的封面/目录/教学目标页时，读取 [生产细则](references/production-guidance.md)。普通文本正文批次不加载该参考文件。

只有已经按 8 页完成 `Plan`、并实际读取当前批次约 5 分钟后仍没有可提交结果时，才允许把本批缩小到 2–4 页并先提交已完成内容；这是一项运行中止损措施，不是普通批次的预设页数。不要为了少量边角问题让一个普通批次运行二十分钟，也不要用全面回归替代继续读书。

遇到状态冲突时，立即丢弃本批次并停止；不得改用当前新页码重跑，也不得在同一用户回合继续提交。没有任何新记录通过硬门禁时不得推进页码。

## 问答写法

每条记录使用：

```json
{"messages":[{"role":"user","content":"问题"},{"role":"assistant","content":"答案"}]}
```

- 一条围绕一个可检索的技术任务；完整工艺步骤或共同决定结果的一组参数可以放在一条中。
- 问题写清对象、系统、材料、工况或必要前提。答案直接给结论和必要条件，不扩写书外建议。
- 同一主题的定义、用途、条件、方法、参数、故障原因和判据，只要答案不重复，可以分别成问。
- 表格按材料、工况、区间或实际查询任务拆分；避免逐单元格机械改数字，也避免把大量参数塞进一条巨型答案。
- 软件操作只有在改变几何、工艺、参数、刀轨、边界条件、仿真或结果判断时才生成；纯菜单导航跳过。
- 图样内容只有在能用文字唯一说明零件、结构、加工部位和条件时才生成。

## 必须拦截的问题

以下内容不能进入 JSONL，应当就地补全或丢弃：

- 依赖当前书页的说法，如“书中列出”“按文中定义”“见图2-3”“表1-5中”“第20页”。
- 教材元信息或教学设计，如“这本书的内容定位是什么”“项目内容如何组织”“适合哪些读者”。
- 复述知识目标、能力目标或学习目标，如“项目一要求学习哪些知识”“完成任务后应具备什么能力”“引导案例是什么”。
- 缺少可迁移技术任务的案例查数，如只问某教学示例的外形尺寸、厚度、编号、分值或规定采用何种任务形式。
- 依赖未提供案例上下文的“点1”“N10程序段”“第二轮”“程序001中”“基准A”“图中上方”。
- 仅给出类似 `T4 D04` 与 `T4 D12` 的局部代码，却没有从源页确认数控系统、指令含义和选择规则。模型不能靠猜测补齐系统差异。
- 源页无法确认的数值、单位、公式、因果、标准要求或经验性建议。
- 问题或答案为空、角色错误、JSON 结构错误、精确重复问题，以及超过 600 字且密集罗列多个数值区间的参数倾倒。

能从当前页或紧邻页明确补全对象和条件时直接改写，不为这类修复建立长期问题清单。无法补全就跳过，继续提取其他可用知识。

## 修复与严格审计

- 用户指出具体坏数据时，直接修复受影响记录，并把同类确定性模式加入轻量校验；不要自动启动全书审计。
- 普通用词警告、近义重复和答案相似只抽样查看，不自动删除大批数据。
- 只有用户明确要求“严格审计、证据映射或逐页验收”时，才临时建立所需证据和报告；审计产物不得成为以后批量生成的默认依赖。
- 完成整书的条件只有：下一页超过总页数、最终 JSONL 结构校验通过、没有确定性禁用模式。无需双 reviewer、全书账本对账或逐页哈希。

状态和提交使用 [qa-work.ps1](scripts/qa-work.ps1)，轻量成品检查使用 [validate-jsonl.ps1](scripts/validate-jsonl.ps1)。
