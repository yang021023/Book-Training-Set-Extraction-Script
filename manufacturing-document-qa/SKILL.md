# 制造书籍批量问答生成

目标是把大量书籍转成覆盖充分、数量充足、能脱离原书理解的训练问答。默认是“批量生产模式”，不建立长期审计型证据链，但每个临时批次必须有逐页、源页事实驱动的知识单元覆盖清单，防止公式、条件和选择关系被整页漏掉。

## 文件结构

```text
工作区/
├─ 书名.pdf
├─ 书名.jsonl
├─ _qa_work/书名/state.json
└─ manufacturing-document-qa/
   ├─ SKILL.md
   ├─ agents/openai.yaml
   ├─ package.json
   ├─ package-lock.json
   └─ scripts/
```

- 最终 JSONL 每行只含 `messages`。
- 每本书只长期保留一个小型 `state.json`，记录 PDF、JSONL、总页数和下一页。
- 不建立长期 ledger、逐条 evidence、reviewer、Markdown 报告或长期截图/OCR 缓存。逐页覆盖清单只存在于临时批次中，提交成功后随批次删除。
- 临时批次放 `_qa_work/tmp`，提交成功立即删除。
- PDF 解析依赖由 `package.json` 和 `package-lock.json` 声明，不把 `node_modules` 或 Node 可执行文件提交进 Skill。首次使用或依赖缺失时，在工作区运行 `npm install --prefix manufacturing-document-qa`；随后 `.mjs` 脚本只读取 Skill 内安装的 `node_modules`。

## 书籍文件命名规则

- 新建书籍状态时，先读取实际 PDF 文件名；去掉末尾的 `.pdf` 后，将其完整字符串作为 JSONL 的基本文件名和 `book_id`，JSONL 只把扩展名改为 `.jsonl`。
- 必须保留原文件名中的书名、卷次、版本、出版社、来源标记、括号、空格及中英文标点，不得自行简称、翻译、重排或删除。例如：`《机械加工工艺手册》第1卷：工艺基础卷.(第二版) (机械工业出版社) (z-library.sk, 1lib.sk, z-lib.sk).pdf` 对应 `《机械加工工艺手册》第1卷：工艺基础卷.(第二版) (机械工业出版社) (z-library.sk, 1lib.sk, z-lib.sk).jsonl`。
- `book_id` 同样使用去掉 `.pdf` 的完整文件名，以便跨会话按同一名称恢复。若已有状态或 JSONL 使用旧的简化名称，继续处理前先迁移为该规则；不得同时保留两个状态或两个输出文件。
- PDF 位于工作区子目录时，JSONL 保持在同一目录，并在 `state.json` 中记录相对工作区根目录的路径；不得为套用命名规则改动 PDF 文件名。

## 默认批量生产

### 上下文与命令输出控制（硬约束）

- 禁止对工作区、`manufacturing-document-qa`、`_qa_work` 或 `node_modules` 执行无边界递归枚举。查找书籍和状态时只查询目标扩展名、目标目录或已知 `book_id`；不得把依赖目录清单发送进会话。
- PowerShell 诊断输出必须先投影为少量标量字段。不得把 `Get-Content` 返回对象、`FileInfo` 的 Provider/PSDrive 属性或其他嵌套系统对象直接交给 `ConvertTo-Json`；统计行数使用 .NET 文件 API并只输出路径、行数、字节数等必要字段。
- 除当前语义批次的正文/OCR外，单次诊断输出应控制在约 10,000 字符以内。发现输出截断、对象属性异常展开或预计超过范围时，立即停止该诊断分支，不得换一种方式重复倾倒同一批内容。
- JSONL 校验必须通过 `qa-work.ps1 -Action Validate -BookId <已绑定 book_id>` 执行，不直接拼接 `validate-jsonl.ps1` 参数。校验使用单独工具调用，不与临时文件删除、`Resume` 或其他命令串联；这样校验失败不会掩盖清理和状态核对结果。

### 会话与书籍绑定（硬约束）

- 一个会话最多处理一本书。新会话首次选定、`Resume`、`Plan` 或处理某本书后，该会话即永久绑定这个 `book_id`；绑定在整个会话生命周期内不可更换，包括该书完成以后。
- IDE 活动文件、打开的 OCR 标签和用户后续提到的其他书名，只能在会话尚未绑定时用于选书。会话一旦绑定，任何这些变化都不得触发切书。
- 绑定书完成后，用户再说“继续”“接着”“下一批”“往下做”等，只允许对原 `book_id` 执行 `Resume` 或直接依据已核对状态报告“该书已完成”，随后停止。严禁 `List` 后选择另一书，严禁对另一 `book_id` 执行 `Resume`、`Plan`、提取、渲染、OCR、创建批次或 `Commit`。
- 即使用户在已绑定会话中明确要求处理另一书，也必须停止并提示其新建会话；不得在当前会话切换。新书只能在新会话开始。
- 一本书可以因上下文长度而由多个会话先后接力，但旧会话必须停止，不能与新会话同时处理；新会话使用同一 `book_id` 执行 `Resume`，以 `state.json` 为准。
- 若发现当前会话已经触及第二本书，立即停止第二本书的未提交工作并清理其当前批次临时文件，不得继续提交。若第二本书已被误提交，不得自行删除记录或回退状态；应报告涉及的 `book_id`、页码和记录数，等待用户在正确会话中决定如何处理。

#### 继续请求的决策门禁

每次收到“继续”“接着”“下一批”等请求，先按会话历史判断是否已有绑定的 `book_id`，再决定是否调用脚本：

- 已绑定且书籍仍为 `active`：只允许对该 `book_id` 执行 `Resume`、`Plan` 和当前批次流程；不得用 `List` 重新选书。
- 已绑定且书籍为 `completed`：只允许对该 `book_id` 执行一次 `Resume` 核对，或直接报告已完成，然后停止；不得把“继续”解释为“下一本”。
- 尚未绑定：只有用户明确点名书籍，或 `ActiveFile` 唯一映射到一本书时才能绑定；若“继续”无法唯一确定书籍，列出状态后必须等待用户指定，不得因只剩一本 active、活动标签变化或最近打开的 JSONL 而自行绑定。
- 绑定判定完成前不得创建批次、提取页面、渲染、OCR 或 `Commit`；所有脚本调用都必须显式使用与绑定一致的 `-BookId`。发现拟调用的 `BookId` 与绑定不一致时，立即停止并请求新会话。

1. 仅在新会话尚未绑定书籍时运行 `powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts/qa-work.ps1 -Action List`。用户点名或 IDE 有 `Active file` 且能唯一映射时直接 `Resume` 对应书；首次绑定后保存 `book_id`，后续所有 `Resume`、`Plan` 和 `Commit` 都必须显式使用这个 `book_id`。已绑定会话即使书籍完成，也不得通过 `List` 选择下一本。
2. 首次使用 `Plan` 时仍采用默认 8 页，但这 8 页只是候选阅读窗口，不是固定提交边界。阅读后应按知识单元是否完整来确定最终 `end_page`：定义与条件、公式与符号说明、成套工艺步骤、表格表头与必要续表、故障原因与验证结论、案例分析链条等应尽量放在同一批内。章节或小节结束是重要边界信号，但不是唯一依据。若候选窗口内平均每页出现 3 个以上独立知识单元，优先把最终批次缩为 3～5 页的完整子单元，降低跨页漏项风险。
   - 若一个完整知识单元在第 6、7 页等位置结束，而后续页已开始不相干的新主题，可把本批前缩到该闭合点；已经预览但未纳入最终范围的页面不得生成本批问答，也不得推进状态。
   - 若候选窗口最后一页仍处于同一知识单元中，应以 1～2 页为步长向后预览，并延伸到最近的语义闭合点，例如第 9 页恰好结束该知识点时就提交 9 页。不要为了凑成 8 页而截断知识链，也不要仅为凑页数跨入新的无关主题。
   - 边界调整后，用明确的 `-BatchPages N` 再执行一次 `Plan`，使最后一次计划范围与最终提交范围完全一致。脚本支持单批 1～12 页；12 页是上下文保护上限，不是目标页数。若一个知识点超过这一窗口，应在其内部最近的可独立理解的子单元处切分。
   到书末自动缩短，绝不越过 PDF 实际页数。为判断边界而多次调用 `Plan` 或增量提取相邻页仍属于同一批次；一次用户“继续”只授权当前一个语义批次和最多一次 `Commit`。`Commit` 成功后，本回合只允许删除本批及边界预览临时文件、用 `Resume` 核对状态，并在达到约 100 条增量或整书完成时单独执行一次 `Validate`，随后向用户汇报；禁止继续规划或处理下一批、创建下一批文件或执行第二次 `Commit`。单独的“继续”不表示连续运行；只有用户明确要求“连续处理 N 批”“处理到第 X 页”或“完成整本”时，才可在同一回合处理多批。
3. 优先提取 PDF 文本。文本层为空或明显损坏时才渲染对应页；扫描页渲染后先使用 [ocr-images.ps1](scripts/ocr-images.ps1) 做本地中文 OCR，再阅读 OCR 文本。只要页面包含公式、数值关系、代码、表格、结构图或角度/尺寸关系，就必须回看该页原图；不能以 OCR 看似连贯为由跳过。不得因为上一批是扫描页就跳过本批的文本提取检查。
4. 阅读当前批次后，先在临时批次的 `coverage` 中按页列出知识单元，再生成问答。**先完成源页清单，后检索既有 JSONL；不得倒置。** 知识单元必须是可独立检索的最小技术事实，不能用“本页介绍切削力”“某表给出参数”等笼统摘要代替多个事实。至少逐项检查：定义、作用、组成、公式与每个关键符号、成立条件、参数与单位、因果关系、比较、步骤、选择方法、限制条件、故障原因、结果判据以及表格中的实际选择关系。
   - 一条公式与其适用条件、符号含义或由其导出的独立计算任务分别构成单元；不要用一条“公式是什么”覆盖所有内容。
   - 同一对象的用途、工作原理、优缺点、适用限制、测量/选用方法，答案不重复时分别构成单元。
   - 表格按真实决策关系拆分：表头含义、适用对象、区间/等级选择、关键差异和修正条件可分别成单元；不得逐格抄数，也不得只用一条概括问答覆盖整张表。
   - 每个技术单元必须写 `source_type` 和 `source_fact`：前者标识它是定义、公式、条件、关系、步骤、比较、选择、测量、表格或图示；后者写出源页上的具体事实（公式要保留关键符号，表格要说明行列或选择关系）。这不是长期证据链，只是本批防漏清单。
   - 每个知识单元必须二选一：用 `question` 精确引用一条候选问题，或用 `skip_reason` 说明为什么不能形成独立问答。只有“已有问答充分覆盖”这一跳过理由时，必须同时填写 `covered_by`，逐条列出已存在 JSONL 中能覆盖该具体源页事实的精确问题；一条泛化问题不能据此覆盖同页其他公式、数值、条件、比较或选择关系。非技术页使用 `kind: "nontechnical"` 并填写 `reason`。这是生成时的轻量覆盖检查，不启动第二轮审计，也不长期保存。
5. 把准备写入的记录和逐页 `coverage` 组成临时批次，执行 `Commit`。脚本只保留通过硬门禁且不与现有问题精确重复的记录，并要求覆盖页码完整、每条候选问题都被知识单元引用、每个知识单元都有问题或跳过理由。普通技术页按每页至少约 3 条计算低产复查门槛；通过数量低于 `ceil(技术页数 × 3)` 时，脚本拒绝推进页码并保留临时批次。此门槛只用于触发复查，不是凑数目标；若逐页复查确认内容确属稀疏，才可显式加 `-LowYieldReviewed` 放行，禁止第一次提交就使用该参数。提交成功后脚本原子更新 JSONL 和 `state.json`，删除临时批次，并在状态中保留最近 20 次提交的页码、候选数、通过数、过滤原因和每页产量。
6. 每新增约 100 条或整书完成时，显式使用已绑定的 `book_id` 运行一次 `qa-work.ps1 -Action Validate`。普通警告只供抽查，不阻止继续；不要每批重复扫描整本 JSONL，也不要直接调用底层校验脚本。

一个批次通常应产生约 15–50 条；高密度正文可超过该范围。数量只是漏项提示，不是凑数配额，最终以逐页知识单元覆盖为准。正文稀疏时可以更少，但必须通过 `coverage` 说明该页实际知识单元及跳过原因。图册和规格表不能只合并成一两条笼统问答；应按真实检索任务拆出类型选择、适用尺寸范围、结构差异和关键动作关系，同时避免逐单元格机械查数。

临时批次格式：

```json
{
  "book_id": "完整 BookId",
  "start_page": 13,
  "end_page": 14,
  "coverage": [
    {
      "page": 13,
      "kind": "technical",
      "units": [
        {"source_type": "公式", "source_fact": "v_c=πdn/1000，d 为切削处直径，n 为主轴转速", "summary": "切削速度计算公式", "question": "旋转加工时切削速度如何计算？"},
        {"source_type": "条件", "source_fact": "公式中的 d 取切削处直径", "summary": "公式中的直径含义", "question": "切削速度公式中的直径取什么位置的直径？"},
        {"source_type": "关系", "source_fact": "由 v_c=πdn/1000 可反算 n", "summary": "切削速度与转速换算", "question": "已知切削速度和直径时如何确定主轴转速？"},
        {"source_type": "图示", "source_fact": "案例图仅标出孤立尺寸，未给出可迁移工况", "summary": "孤立案例尺寸", "skip_reason": "缺少可迁移的工况，不能形成独立问题"}
      ]
    },
    {"page": 14, "kind": "nontechnical", "reason": "版权信息", "units": []}
  ],
  "records": [
    {"messages": [{"role": "user", "content": "旋转加工时切削速度如何计算？"}, {"role": "assistant", "content": "……"}]},
    {"messages": [{"role": "user", "content": "切削速度公式中的直径取什么位置的直径？"}, {"role": "assistant", "content": "……"}]},
    {"messages": [{"role": "user", "content": "已知切削速度和直径时如何确定主轴转速？"}, {"role": "assistant", "content": "……"}]}
  ]
}
```

`coverage` 必须逐页连续覆盖最终计划范围。它只用于提交门禁，不写入最终 JSONL。

### 已处理页回检与补充

用户要求“重新检阅、补充前面、前面太少、提高已有部分质量”时，进入回检模式。回检只补充遗漏问答，不回退或推进正常阅读进度：

1. 先用已绑定的完整 `book_id` 执行 `Resume`，确认正常阅读的 `next_page` 和已处理范围。回检范围必须落在 `1..next_page-1`；整书已完成时可落在 `1..page_count`。
2. 每批通常复查 3～6 页。必须先按源页重新建立逐页知识单元清单，再读取或检索已有 JSONL 判断哪些问题已经覆盖。现有问答只用于去重，不能作为源页检查清单；不能因为已有一条概括性问题就推定同段中的公式、数值、条件、比较和限制均已覆盖。回检的最小闭环是“源页具体事实 → 原子知识单元 → 旧问题精确比对 → 新问题或可核验跳过理由”，不是“按主题搜到若干旧问答”。
3. 对扫描页按 [生产细则](references/production-guidance.md) 重新 OCR；含公式、数值关系、代码、表格、结构图或角度/尺寸关系的页逐页查看原图。回检不能仅搜索 OCR 关键词或只重读已有问答。
4. 为所有源页知识单元建立 `coverage`，只把真正缺失的问题放入 `records`。已被现有 JSONL 充分覆盖的单元填写 `skip_reason: "已有问答充分覆盖"`，并以 `covered_by` 列出实际存在的精确问题；脚本会核验这些问题确实已在 JSONL 中。只有答案能覆盖该单元 `source_fact` 的关键对象、关系与条件，才算充分覆盖。无法脱离页面成立的内容写明其他具体原因。不要为了规避重复而改写出同义问题。
5. 使用 `qa-work.ps1 -Action Augment -BookId <完整 BookId> -BatchFile <批次文件>` 追加。不得使用 `Commit`、`SetNext` 或修改 `state.next_page` 来补旧页。低于 `ceil(技术页数 × 3)` 时先按源页补查；确属稀疏才可在第二次调用中加 `-LowYieldReviewed`。
6. `Augment` 成功后删除本批 OCR、页面图和边界预览文件，再执行一次 `Resume`，核对 `record_count` 已增加且 `next_page` 完全不变。一次普通“继续回检”最多成功追加一个批次。

每页 3 条只是触发低产复查的最低门槛，不是完成标准，也不是停止条件。高密度页面应继续覆盖全部可独立检索的知识单元；如果原页可形成 8 条而已有 2 条，应补缺失的 6 条，而不是补到总计 3 条就结束。低产放行不是“本页已有类似主题问答”的许可：必须先完成所有原子单元，并让每个“已有覆盖”单元给出可核验的 `covered_by`。

处理扫描 PDF、图样/规格表密集章节、上下文压缩后的恢复，或新书首批的封面/目录/教学目标页时，读取 [生产细则](references/production-guidance.md)。普通文本正文批次不加载该参考文件。

语义边界调整必须依据实际内容，不得因为超时、会话错误或上下文压缩而随意缩小批次。只有实际读取约 5 分钟后仍没有可提交结果时，才可选取已经确认完整的 2～4 页最小知识单元作为运行中止损；不能把尚未讲完的定义、公式、步骤、表格或论证链截断。不要为了少量边角问题让一个批次运行二十分钟，也不要用全面回归替代继续读书。

遇到状态冲突时，立即丢弃本批次并停止；不得改用当前新页码重跑，也不得在同一用户回合继续提交。没有任何新记录通过硬门禁时不得推进页码。

### 纯编号页跳过

若用户明确要求排除低训练价值的书内、企业或版本专用编号速查页，且逐页确认其只有“编号—名称”对应而没有可迁移的定义、原理、选用条件、工艺关系或检验判据，不得为推进页码编造问答。完成 `Resume`、候选 `Plan`、OCR 和必要原图回看后，使用 `qa-work.ps1 -Action Skip -BookId <完整 BookId> -BatchPages N -SkipReason <具体原因>` 记录连续纯编号页的跳过理由。`Skip` 不写入 JSONL，只允许从 `state.next_page` 开始，并在状态中保留页码和理由；调用后仍须 `Resume` 核验。不得把标准中可跨企业、跨设备使用的材料牌号、尺寸公差、工艺条件或安全要求误判为纯编号页。

## 问答写法

每条记录使用：

```json
{"messages":[{"role":"user","content":"问题"},{"role":"assistant","content":"答案"}]}
```

- 一条围绕一个可检索的技术任务；完整工艺步骤或共同决定结果的一组参数可以放在一条中。
- 问题写清对象、系统、材料、工况或必要前提。答案直接给结论和必要条件，不扩写书外建议。
- 同一主题的定义、用途、条件、方法、参数、故障原因和判据，只要答案不重复，可以分别成问。
- 表格按材料、工况、区间或实际查询任务拆分；避免逐单元格机械改数字，也避免把大量参数塞进一条巨型答案。
- 软件操作只有在改变几何、工艺、参数、刀轨、边界条件、仿真或结果判断时才生成；纯菜单导航跳过。
- 图样内容只有在能用文字唯一说明零件、结构、加工部位和条件时才生成。

## 必须拦截的问题

以下内容不能进入 JSONL，应当就地补全或丢弃：

- 依赖当前书页或教材示例的说法，如“书中列出”“按文中定义”“见图2-3”“表1-5中”“第20页”“示例中的”“在示例条件下”。即使问题或答案同时抄出了部分参数，也必须改写成明确对象与完整工况，不能把“示例/案例”当作事实来源。
- 教材元信息或教学设计，如“这本书的内容定位是什么”“项目内容如何组织”“适合哪些读者”。
- 复述知识目标、能力目标或学习目标，如“项目一要求学习哪些知识”“完成任务后应具备什么能力”“引导案例是什么”。
- 缺少可迁移技术任务的案例查数，如只问某教学示例的外形尺寸、厚度、编号、分值或规定采用何种任务形式。
- 依赖未提供案例上下文的“点1”“N10程序段”“第二轮”“程序001中”“基准A”“图中上方”。
- 仅给出类似 `T4 D04` 与 `T4 D12` 的局部代码，却没有从源页确认数控系统、指令含义和选择规则。模型不能靠猜测补齐系统差异。
- 源页无法确认的数值、单位、公式、因果、标准要求或经验性建议。
- 问题或答案为空、角色错误、JSON 结构错误、精确重复问题，以及超过 600 字且密集罗列多个数值区间的参数倾倒。

能从当前页或紧邻页明确补全对象和条件时直接改写，不为这类修复建立长期问题清单。无法补全就跳过，继续提取其他可用知识。

## 修复与严格审计

- 用户指出具体坏数据时，直接修复受影响记录，并把同类确定性模式加入轻量校验；不要自动启动全书审计。
- 普通用词警告、近义重复和答案相似只抽样查看，不自动删除大批数据。
- 只有用户明确要求“严格审计、证据映射或逐页验收”时，才临时建立所需证据和报告；审计产物不得成为以后批量生成的默认依赖。
- 完成整书的条件只有：下一页超过总页数、最终 JSONL 结构校验通过、没有确定性禁用模式。无需双 reviewer、全书账本对账或逐页哈希。

状态、提交和按书校验统一使用 [qa-work.ps1](scripts/qa-work.ps1)；[validate-jsonl.ps1](scripts/validate-jsonl.ps1) 是由前者调用的底层轻量检查器，不在普通批量流程中直接调用。
